# AWGdocker

[English README](README.md)

Один Docker-образ userspace AmneziaWG для обоих пиров. Роль сервера или клиента
задаётся конфигурацией. Общий manifest содержит `linux/amd64` и `linux/arm64`.

Здесь только обезличенные примеры. Туннельные адреса `10.203.0.1/32` и
`10.203.0.2/32` выбраны произвольно; замените их при пересечении с вашими сетями.
Инструкция соединяет два AWG-пира. Настройка внешнего роутера, LAN-шлюза,
маршрутизации домашних устройств, NAT и выхода в интернет сюда не входит.

## Автоматическая сборка и публикация

- Каждый день в **04:23 UTC** GitHub Actions проверяет цифровые стабильные Git-теги
  официальных `amneziawg-go` и `amneziawg-tools`. Бета-версии и rc исключены.
  GitHub Releases не обязательны: движок может публиковать только теги.
- Новый тег или изменившийся commit за тегом вызывает сборку. Если входные данные
  уже опубликованы, запланированная проверка пропускает сборку в любой день недели.
  Обязательных еженедельных пересборок нет.
- Push в `main` и ручной запуск workflow также вызывают сборку. Публикация разрешена
  только из `main`; pull request и ручной запуск другой ветки проверяются без публикации.
- Версии один раз разрешаются в точные commit ID. Обе архитектуры используют одну
  и ту же пару исходников, а не изменяемую ветку upstream.
- На каждой архитектуре проверяются handshake, ping в обе стороны, клиентский
  default route, read-only sysctl и выполнение down hooks при корректной остановке.
- Только успех обеих архитектур продвигает общий `latest`. Если вторая архитектура
  или публикация общего manifest упали, отдельные architecture-теги могут остаться.
- Тег `build-RUN_ID-ATTEMPT` обозначает одну публикацию. Для установки используйте
  **digest общего manifest**. `latest` удобен для поиска, но не гарантирует совместимость.
- Workflow не подключается к вашим устройствам и не устанавливает обновления.

Образ публикуется в `ghcr.io/konkere/awgdocker`. Digest берите из успешного
[запуска Actions](https://github.com/konkere/AWGdocker/actions/workflows/build.yml).
Локальные проверки не заменяют успешную сборку опубликованного workflow.

Событие release чужого репозитория напрямую этот workflow не запускает: изменения
обнаруживаются ежедневным опросом. Внешний webhook или GitHub App не требуются.
GitHub может задерживать schedule, а после 60 дней без активности публичного
репозитория — отключить его. Проверяйте историю запусков и при необходимости
включайте workflow снова.

## Требования и получение файлов

Оба хоста: Linux amd64 или arm64, Docker Engine с Compose v2 и `/dev/net/tun`.
Контейнерам нужна capability `NET_ADMIN`; `privileged: true` не требуется.
UDP-порт сервера должен быть доступен клиенту.

Для генерации ключей нужна доверенная машина с Bash и Docker, для локальной
сборки — дополнительно Git и Python 3.

```bash
timeout 120 git clone https://github.com/konkere/AWGdocker.git
cd AWGdocker
```

Новый пакет GHCR может быть приватным даже при публичном репозитории. Для pull
без авторизации владелец должен сделать **сам пакет** публичным. Для приватного
пакета устройствам нужен разрешённый доступ к registry.

## Быстрое развёртывание AWG ↔ AWG

1. Выберите digest общего образа из успешной сборки. Ниже `REPLACE_WITH_DIGEST`
   нужно заменить настоящим digest. Адрес `203.0.113.10` используется только для
   документации — подставьте адрес сервера.

   ```bash
   export AWG_IMAGE='ghcr.io/konkere/awgdocker@sha256:REPLACE_WITH_DIGEST'
   export ENDPOINT='203.0.113.10:443'
   timeout 300 docker pull "$AWG_IMAGE"
   bash scripts/generate-example.sh
   ```

2. Генератор создаёт `private-configs/server/awg0.conf` и
   `private-configs/client/awg0.conf`. Каталоги имеют права `700`, файлы — `600`.
   Для защиты от перезаписи нужен новый выходной каталог. Для другой пары:

   ```bash
   bash scripts/generate-example.sh ./another-private-pair
   ```

   Файлы содержат закрытые и общие ключи. Не помещайте их в Git, логи или issues.

3. По защищённому каналу скопируйте серверный конфиг в приватный каталог
   развёртывания на сервере, клиентский — в отдельный каталог на клиенте.
   В каждый каталог положите соответствующий файл из `examples/` под именем
   `compose.yml`: `server.compose.yml` либо `client.compose.yml`.

4. В каждом каталоге развёртывания создайте `.env` с одним и тем же digest:

   ```bash
   umask 077
   printf '%s\n' 'AWG_IMAGE=ghcr.io/konkere/awgdocker@sha256:REPLACE_WITH_DIGEST' > .env
   chmod 600 awg0.conf .env
   ```

5. Сначала на сервере, затем на клиенте:

   ```bash
   unset AWG_IMAGE
   timeout 10 docker compose config -q
   timeout 300 docker compose pull awg
   timeout 90 docker compose up -d --no-build --pull never awg
   ```

   Экспортированная в shell переменная `AWG_IMAGE` имеет приоритет над `.env`
   и `--env-file`, поэтому перед использованием этих файлов её нужно сбросить.

6. На клиенте:

   ```bash
   timeout 10 docker exec awg-client ping -c3 -W2 10.203.0.1
   timeout 10 docker exec awg-client awg show awg0 latest-handshakes
   ```

   На сервере:

   ```bash
   timeout 10 docker exec awg-server ping -c3 -W2 10.203.0.2
   ```

Пример соединяет только два туннельных адреса; трафик хоста и LAN автоматически
через туннель не пойдёт. Серверный bridge публикует UDP/443. TCP/443 независим,
но HTTP/3 также использует UDP/443 и будет конфликтовать с этим примером.

Генератор использует порт 443 **внутри** серверного контейнера. Если в `ENDPOINT`
указан другой внешний порт, измените серверный Compose на `"ВНЕШНИЙ_ПОРТ:443/udp"`.

Базовый пример не включает необязательные `I1`, `RandomTrailers` и padding.
CI отдельно проверяет базовый и расширенный набор параметров на обеих архитектурах.
Дополнительную настройку добавляйте после проверки базовой связи.

## Локальная сборка

```bash
bash scripts/build-local.sh
```

Скрипт выбирает последние стабильные теги и записывает `upstream.json`. Результат —
`amneziawg:local` для архитектуры текущего хоста. Для другого локального тега:

```bash
IMAGE=amneziawg:candidate bash scripts/build-local.sh
```

Если Docker bridge не имеет выхода в сеть:

```bash
BUILD_NETWORK=host bash scripts/build-local.sh
```

Dockerfile получает `AWG_GO_COMMIT` и `AWG_TOOLS_COMMIT`; постоянных значений
версий по умолчанию нет. `AWG_GO_TAG` и `AWG_TOOLS_TAG` служат метаданными.
Разрешённые версии записываются в `upstream.json` и OCI labels.

При сборке загружаются и соответствующие исходники распространяемых компонентов.
Нужны дополнительное время, место и доступ к серверам исходников Alpine.
Базовые образы обновляются через `--pull`. Одинаковых AWG commit недостаточно
для побайтового воспроизведения всей ОС: понадобятся также digest базовых образов
и снимки пакетов/зависимостей. Сохраняйте опубликованный digest и запись сборки.

Для локального образа задайте `AWG_IMAGE=amneziawg:local`, пропустите registry pull
и используйте `--pull never`. На каждом хосте должен существовать образ его
архитектуры: один amd64 tar не работает как arm64.

Проверка временной пары на отдельной тестовой машине с Docker и `/dev/net/tun`:

```bash
for mode in basic advanced; do
    SMOKE_MODE="$mode" timeout 240 bash scripts/smoke.sh amneziawg:local
done
```

Тест создаёт временную Docker-сеть и два контейнера, генерирует одноразовые ключи
и удаляет ресурсы после завершения. Он не использует рабочие конфиги и не проверяет
реальную LAN, macvlan или интернет-маршрутизацию.

Offline-проверки, без Docker daemon и сети:

```bash
python3 -m unittest discover -s tests -v
```

## Ручное обновление и откат

Прочитайте изменения upstream. Успешный CI новой пары не доказывает совместимость
со старым установленным пиром. Держите оба конца на одном выбранном выпуске.

Перед переключением:

- Приватно сохраните `compose.yml`, `.env`, `awg0.conf` и их права.
- Узнайте `.Image` работающего контейнера и пометьте **именно этот ID** тегом
  `awg-rollback:TIMESTAMP`; сохраните образ или экспортируйте его. Отдельно сохраните
  старый `.env`.
- Создайте `.env.next` из `.env`, поменяв только `AWG_IMAGE` на новый общий digest.
- Сбросьте экспортированный `AWG_IMAGE`; через `config --images` проверьте выбор образа.
- Выполните `docker compose --env-file .env.next config -q`.
- Заранее загрузите образ на обоих устройствах через
  `timeout 300 docker compose --env-file .env.next pull awg`.
  Сам по себе pull работающий контейнер не обновляет.
- Если изменился протокол или формат конфига, обеспечьте независимый доступ
  к обоим хостам и согласованное переключение.

Установите `.env.next` как `.env`, затем сначала на сервере, потом на клиенте:

```bash
timeout 90 docker compose up -d --no-build --pull never awg
```

Проверьте свежие handshake и ping в обе стороны. Старые образы оставьте до
подтверждения устойчивой работы. При сбое укажите в `AWG_IMAGE` сохранённый
локальный тег отката каждого хоста и повторите `up` с `--pull never`.

Если менялся конфиг: **остановите контейнер до восстановления файла**, чтобы
down hooks завершились с прежними настройками. Затем восстановите конфиг и выполните:

```bash
timeout 90 docker compose up -d --force-recreate --no-build --pull never awg
```

`docker compose restart` не применяет новый образ.

## Особенности эксплуатации

Модуль ядра не нужен: проверяемая точка переопределения upstream принудительно
выбирает `amneziawg-go`, даже при доступном модуле на хосте.
Отдельная правка не пишет `src_valid_mark`, если Compose уже выставил `1`.
Если ожидаемое место upstream изменится, сборка завершится ошибкой для проверки.

Entrypoint делает приватную копию стартового конфига и использует её же для down.
Ошибка очистки даёт ненулевой код завершения. Очистка не гарантируется после
SIGKILL, аварии хоста/Docker daemon или частично выполненного `PostUp`.
При host networking перед повторным запуском проверьте остаточные интерфейсы,
маршруты и правила hooks: повторные старты могут дублировать правила.

Не публикуйте обычный `awg show`, `showconf` или `dump`: версии с header protection
могут показать общий `HeaderProtectionKey`. Используйте отдельные поля, например
`latest-handshakes` и `transfer`. Не включайте трассировку shell при генерации ключей.
